# สถาปัตยกรรม (Y1 / B3.1)

```
 เบราว์เซอร์ (React 18 + React Router 6)         ← ไม่มีรหัสลับ เก็บแค่ token ล็อกอิน (sessionStorage)
        │  fetch /api/*  (Bearer token)
        ▼
 Next.js (Vercel / localhost:3000)  ──rewrite──►  Express 4 (localhost:4000)   ← ถือ SUPABASE_SERVICE_ROLE_KEY
                                                       │  supabase-js (query มีพารามิเตอร์)
                                                       ▼
                                              Supabase: PostgreSQL + Auth
                                              (ตาราง · view · RPC · RLS)
```

| อะไรอยู่ฝั่งไหน | ฝั่งผู้ใช้ (เบราว์เซอร์) | ฝั่งเซิร์ฟเวอร์ (Express) |
|---|---|---|
| รหัสลับ service_role | ❌ | ✅ (`server/.env`) |
| anon key | ❌ (ไม่ได้ใช้ในหน้าเว็บ) | ✅ (ใช้ตอนตรวจรหัสผ่าน) |
| ตรวจสิทธิ์ตามบทบาท | แสดง/ซ่อนเมนูเพื่อความสะดวก | ✅ บังคับจริง |
| ตรวจข้อมูลที่กรอก | ✅ ให้ผู้ใช้เห็นเร็ว | ✅ ตรวจซ้ำ (zod) |

## การคำนวณทำที่ไหน (Y1.2)

| การคำนวณ | ที่ทำ | เหตุผล |
|---|---|---|
| เกรดจากคะแนน | ฐานข้อมูล (generated column) | ถูกต้องเสมอ ไม่ว่าข้อมูลเข้ามาทางไหน |
| ตัวชี้วัดแดชบอร์ด | ฐานข้อมูล (RPC `dashboard_summary`) | ไม่ดึงทั้งตารางมาคำนวณบนเว็บ ตอบเร็ว |
| คุณภาพข้อมูล 4 มิติ | ฐานข้อมูล (RPC `quality_report`) | ใช้ข้อมูลล่าสุดเสมอ |
| ตรวจรูปแบบข้อมูลนำเข้า | Express (zod) | ไม่เชื่อข้อมูลจากเบราว์เซอร์ |
| แปลงวันที่ ค.ศ. → พ.ศ. | หน้าเว็บ (`src/utils/thaiDate.js`) | เป็นเรื่องการแสดงผล |

## จุดที่ล้มเหลวได้และแผนรับมือ (Y1.3)

1. **ฐานข้อมูลหยุด** (โครงการฟรีของ Supabase ถูกพักเมื่อไม่มีการใช้งาน) → ตรวจ `/api/health` ก่อนนำเสนอ และกดปลุกโครงการใน Dashboard
2. **backend ไม่ทำงาน** → หน้าเว็บแสดงข้อความ "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" พร้อมปุ่มลองใหม่
3. **token หมดอายุ** → ระบบพากลับหน้าล็อกอินอัตโนมัติ (ยังไม่มี refresh token)
4. **ข้อมูลเก่า/ยังไม่มีคะแนน** → ทุกหน้าที่มีตัวเลขแสดง "ข้อมูล ณ วันที่ …" และข้อจำกัด
